Failover Test: continuous writes

Start this, then stop the primary MySQL on purpose. The log will show OK lines with the current writer, then ERROR lines while the primary is down, then a RECOVERED line with how many seconds the outage lasted and which server is the new writer. That number is your failover time, measured, not guessed.

How to test failover, in order: 1. Connect above as a ProxySQL user, for example testuser1 on 172.31.4.181:6033. 2. Start the test below. 3. On the current primary DB VM, run sudo systemctl stop mysql. 4. Watch ERROR lines, then RECOVERED, and the writer name change. 5. Start the old primary again with sudo systemctl start mysql, it should rejoin as SECONDARY, writer should stay on the new primary.





Auto mode inserts into app_name, seq, payload columns, so the table must have those columns. Use Create failover_test table above if you do not have such a table, if your user has CREATE privilege, otherwise create it as root on the writer first, then Start. Custom SQL mode runs your INSERT as the connected user, so it can only do what that user can do.






Restore: backup + binlogs to a target server


Pick a server to restore onto, then pick a backup and a binlog. The app loads the backup on that server, then replays the binlogs up to the binlog you picked. The backup list comes from MinIO, using the backup setup already on this server, so no MinIO login is needed here.
